# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Photogether: an Android camera / photo-booth app (Kotlin, Jetpack Compose, CameraX, Room, Koin, OpenGL ES). The viewfinder simulates film cameras (LUT-based looks), and a separate editor applies filters, effects, frames and stickers to captured photos.

Naming quirk: Gradle `namespace` / `applicationId` is `com.tgound.photogether`, but all source packages are `com.example.photogether`. Use the latter in code and test paths.

## Commands

```bash
./gradlew assembleDebug                      # debug APK (Photogether-v1.0-debug.apk)
./gradlew :app:testDebugUnitTest             # all JVM unit tests
./gradlew :app:testDebugUnitTest --tests "com.example.photogether.core.render.RecipeCodeTest"   # one class
./gradlew :app:testDebugUnitTest --tests "*.MomentQueryTest.someMethod"                          # one method
./gradlew :app:connectedDebugAndroidTest     # instrumented tests (device/emulator)
./gradlew assembleDebug -PdebugAbi=arm64-v8a # optional: single-ABI debug build for size-limited uploads
```

- Secrets come from the gitignored root `local.properties` (see `local.properties.example`); `UNSPLASH_ACCESS_KEY` is exposed via `BuildConfig`.
- Release builds use R8 minify + shrink (`app/proguard-rules.pro`).
- Modules: `:app` and `:shared` (Kotlin Multiplatform; commonMain holds `PhotoBooth` / `PhotoBoothLayout` domain models, with an iOS target).
- `.claude/worktrees/` holds agent worktrees; ignore it when searching.

## Architecture

Single-activity Compose app (`MainActivity`, `core/navigation/AppNavigation.kt`), MVVM with Koin DI wired in `core/di/AppModule.kt`.

- `ui/` – Compose screens plus ViewModels: `view/CameraScreen` + `viewmodel/CameraViewModel` (viewfinder), `camera/` (camera picker, "polaroid" cards, 3D camera body), `editor/` (EditorScreen/ViewModel, one panel per tool, undo history), `moments/` (gallery).
- `domain/` – repository interfaces and use cases.
- `data/` – Room `AppDatabase` (entities `PhotoBoothEntity`, `RecipeEntity`; migrations in `data/migration/Migrations.kt`, bump `version` and add a migration on schema change), DataStore-backed settings/prefs, Unsplash Retrofit client, Play Billing (`PremiumRules` gates premium filters), `MomentsRepository`.
- `core/camera/` – Camera2 interop and pure math helpers (exposure, focus, lens selection).
- `core/moments/` – gallery model and query logic.

### Render pipeline (`core/render/`, the core of the app)

Two paths share the same look data:

1. **Live viewfinder**: `FilterSurfaceProcessor` is a CameraX `SurfaceProcessor` that runs its own EGL context on a dedicated thread and draws the camera frames through GL shaders (`Shaders.kt`, `GlRenderer`, `LiveGl`, bloom/grain/skin passes) so the preview is already graded.
2. **Editor / export**: `EditPipeline` (behind the `EditRenderer` interface, faked in tests) always renders from the *original source bitmap* with an `EditSnapshot`; never feed a previous output back in. Order: GPU grade and effects, crop, skin, frame, items/overlays.

Look data:
- `FilterCatalog` loads `assets/filters/catalog.json` (id, name, group, `lut`, `premium`) and 512x512 3D-LUT PNGs from `assets/filters/luts/` (layout documented in `tools/lut-gen/generate_luts.py`). `assets/filters/fx/` holds effect textures.
- `CameraProfiles.kt` defines the selectable camera "bodies" as one `CameraProfile` list (`CameraProfiles.ALL`): each restricts the viewfinder to its own `filterIds`. The Japan pack entries sit between the `BEGIN/END GENERATED` markers, written by `import_cube_pack.py`. `Recipe` / `RecipeCode` encode and share recipes; `RecipeEntity` persists them.
- `EditParams` / `EditSnapshot` / `EditHistory` hold the full editable state; `*Math.kt` files are pure, JVM-testable logic split out from GL code.

### Generated assets

LUTs, `catalog.json`, FX textures and sounds are generated by stdlib-only Python scripts, not hand-edited:

```bash
python3 -I tools/lut-gen/generate_luts.py   # run from repo root; rewrites luts/ and catalog.json (reads tools/lut-gen/japan_pack.json)
python3 -I tools/fx-gen/generate_fx.py
python3 -I tools/sfx-gen/generate_sfx.py
```

When adding a filter, change the generator (or `japan_pack.json` / `import_cube_pack.py` for .cube packs) and regenerate so `catalog.json` and the PNGs stay consistent.

## Testing

Unit tests live in `app/src/test/java/com/example/photogether/` and mirror the main packages. GL code is kept out of tests: test the `*Math.kt` helpers and ViewModels with fakes (e.g. `FakeRecipeDao`). Camera/GL changes need verification on a real device or emulator, not just unit tests.
